# Phase 10 — Release v2: docs, runbook, screenshots, deploy gate

**Folder:** `docs/phases-v2/10-release-v2/`
**Estimate:** 2–3 days · **Depends on:** 09 · **Blocks:** nothing (it is the end)
**Rule:** the release is **documented and gated**, never automatic. Deploying remains an
owner command (`rule.md` §3).

---

## 1. Charter

Make the repository tell the truth about v2: README, screen inventory, data model, rules
and backup versions, CI story, screenshots, changelog, and the owner-executed deploy
runbook. Close the v1→v2 record trail.

## 2. Scope

### In
1. **README rewrite** — what v2 is (beginner-first DSA workspace), the seven surfaces
   (Today · Topics · Problem/theatre · Code · Review · Quizzes · Insights), what changed
   from v1, what is deliberately absent (notes, transcripts, ad-blocking, AI, remote judge),
   and the honest limits (local compiler size, offline behaviour, language support).
2. **Screenshots** — 8 phone + 6 desktop, generated by a Playwright script
   (`tools/screenshots.mjs`) from the seeded emulator, dark and light, committed to
   `docs/screenshots/` with stable filenames so the README never rots.
3. **Docs set, final:**
   - `docs/UI-REFERENCE.md` — tokens v2 (frozen), screen inventory v2, states matrix.
   - `docs/DATA-MODEL.md` — v5 section: `snippets`, `quizResults`, settings fields,
     backup v4, quota v2 table, deletion contract.
   - `docs/DECISIONS.md` — every v2 decision dated (drops, re-baselines, tokens freeze,
     no-ad-blocking stance, notes→code, local runner, CSP decision, dependency removals).
   - `docs/phases-v2/*/RECORD.md` — one per executed phase (CI id, tip sha, preview bytes,
     deviations, what is visible).
   - `docs/CHANGELOG.md` — v2.0.0 entries grouped by surface, written for a user.
   - `docs/RELEASE-RUNBOOK.md` — updated: rules v5 deploy, hosting, rollback, verification
     steps (open `/`, `#/topics`, one problem, one quiz, one run), and the exact commands
     (owner executes).
4. **Content coverage statement** — a truthful table of what content exists (primers,
   statements, hints, quiz items, test cases) so nobody assumes completeness.
5. **Security/rules verification** — `npm run check:rules` clean, rules v5 deployed only by
   the owner, emulator suite green in the same commit, `firestore.rules` regenerated last.
6. **Backup story** — documented v1→v4 import path with the notes migration note, and a
   tested "export → wipe → import" round trip in the e2e suite.
7. **PWA/store metadata** — manifest name/short/theme colours updated for v2, icons
   unchanged (clean-room "DA" monogram), `apple-touch-icon`, OG image regenerated.
8. **Handoff prompt** — `prompt.md` refreshed for whatever comes after v2 (so a future
   chat can continue without re-reading this whole programme).

### Out
Deploying · tagging · publishing the repo · any new feature · pushing to `main`.

## 3. Design spec
No product design work. The README and screenshots must make the *craft* legible in
10 seconds: one hero screenshot (Today with reason chips), then Topics, Problem/theatre,
Code, Quiz, Insights.

## 5. Acceptance
README describes only what exists · screenshots match the current UI (regenerated in the
same commit as the final UI change) · all version numbers consistent across README,
DATA-MODEL, rules, backup and changelog · runbook commands copy-pasteable and correct ·
content coverage table honest · `npm run build`, `test`, `test:rules`, `test:e2e`,
`check:rules`, `check:budgets`, `check:links`, `test:data` all green from a clean clone ·
nothing deployed.

## 6. Exit
Owner reads the README, walks the runbook, and decides whether to deploy — that decision
and its date go into `docs/DECISIONS.md`.
