## Delivered

### Topics and topic pages

- `#/topics` shows all 20 catalogue topics as navigable cards in a semantic list. Cards include problem/level counts, subtopic chips, confidence rings, outcome totals, and per-topic due counts.
- `#/topic/<id>` has Learn, Practice, and Quiz tabs. The tab is URL-backed (`?tab=`), keyboard-operable, and retained in route paths/back-forward navigation. Previous/next topic links and a return to all topics are present.
- Learn presents the deterministic learning path and an explicit primer-pending state. Quiz reports that no questions are authored yet and has a disabled start button. These are intentional: primer and quiz content/engines belong to Phases 03 and 05.
- Practice groups rows by learning-ordered subtopic; curated `learnOrder` takes priority, then difficulty ramp and source order. Filters cover All, Not started, Shaky, and Done, with an empty result state. Rows retain status, bookmark, plan, and outcome interactions.

### Outcome persistence and backup migration

- Added `Outcome = clean | hint | couldnt` as optional progress field `o`. Done rows read old missing values as clean; todo rows carry no `o`; undoing a solved row clears the UI outcome.
- Guest and signed-in cloud progress paths preserve and update outcomes. Firestore Rules v5 validates the enum and forbids outcomes on todo entries. Emulator tests verify all three allowed values and rejection cases.
- Backup writer is schema v4. Imports of schemas 1–3 remain supported; legacy done rows default to clean. Updated generated `firestore.rules` and the generator are in sync.

### Today and search

- Today’s page now foregrounds Continue, the existing Today planner, and a Weakest topic card. Today/pick rows can carry truthful, muted reason chips (`due today`, `shaky — couldn’t last time`, `weakest topic`, `first solve`) where the available state supports them.
- Search remains the existing full-catalogue search, grouped under topic disclosures, with URL-backed query state. Starting from Today’s top-bar search preserves the owning topic group around results.
