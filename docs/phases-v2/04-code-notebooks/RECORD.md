## What is now visible

- **Notes are gone, everywhere.** `NotesView`/`NoteEditor`, the Notes nav item, palette destination and `#/notes` route, the per-row note buttons, `library.ts` note functions/limits, the backup `notes[]` writer, the rules `notes` match block, and `src/markdown.ts` (its only consumers were the note UI) are all deleted; an old `#/notes` bookmark gets the designed not-found screen. Lists are untouched and still filter the sheet.
- **One saved solution per problem.** Sheet rows and topic rows gained an *Add code / Edit code ⌨* menu action and a `⌨ has code` tag (design-system `Tag`); the problem page carries the full panel. The editor is deliberately small, as contracted: a real `<textarea>` (`spellcheck`/`autocapitalize` off, labelled language `<select>`, 8,000-char cap with counter), a scroll-synced aria-hidden line-number gutter, Tab/Shift-Tab indent, Enter auto-indent, ⌘S/Ctrl+S save, explicit Save/Delete with confirms, an Esc/Close unsaved-changes guard, a ≤500-char plain-text reminder, and an `aria-live` status line reading `Saving… / Saved ✓ / Offline — will sync / Unsaved changes`. No CodeMirror/Monaco, no syntax highlighting.
- **Peek for recall.** The view panel blurs the code behind *Reveal — I've attempted it*; the blurred `<pre>` is `aria-hidden` and unselectable so screen readers can't leak it. Reveal state is component-local (resets on unmount, never stored). Copy-out is one tap: *Copy code* (clipboard, with honest `Copied ✓` feedback), *Open in LeetCode* when the row has that link, and *Open in Compiler Explorer* (the code is never put in a URL). A saved `verdict` shows as a chip; the Phase 07 runner will write it.
- **`#/code` is a real screen.** Search matches problem title, code text and reminder; language and topic filters live in the URL (`?q=&lang=&topic=`), newest first, back-button friendly. Rows carry title, topic · subtopic, language chip, relative age, reminder, *Copy* and *Open problem*; they render through CSS `content-visibility` so all 631 possible solutions stay cheap. Signed-out and no-solutions states are designed `Empty` states with one primary action; signed-in users see a `N saved · M shown` count. The shell nav shows the saved count beside *Code*.
- **Offline works like progress.** Saves are fire-and-forget Firestore writes over the persistent cache; the snapshot's `hasPendingWrites` plus a per-render `navigator.onLine` read drive the status line and the shell *Changes pending* label. Saved code requires sign-in (private account data); the sheet and `#/code`'s signed-out explanation keep working signed out. Per-uid state resets on sign-out/account switch, so one account's code is never shown to another.
- **Backup is schema v5 and says what it did.** Exports write `snippets[]` and no top-level `notes[]`; the account panel counts saved solutions. Importing schemas 1–4 migrates each legacy note into a snippet — old code byte-for-byte, markdown dropped except a ≤500-char plain-text tail — and the preview prints a warning naming every shortened problem before *Replace my progress* is armed.

- **Editor scope held to the PLAN, not the wireframe's extras.** No verdict picker (schema field preserved/displayed; the runner writes it in Phase 07), no title sort (`#/code` is newest-first per §3 scope text), no `highlight.ts` tokenizer (explicitly optional; the budget said no), no drill-row badges (sheet + topic rows + problem page carry `⌨ has code`), no JS list windowing (CSS `content-visibility` covers the §7 "past 200 rows" goal for ≤631 rows), and no "hide again" on peek (reveal-only per contract).
- **Save-status implementation note.** `online` is read from `navigator.onLine` on each render instead of listener state: every moment the label can change already re-renders via a snapshot or an edit, so the read is fresh at the moments that matter (including Playwright's `setOffline`). The editor remounts when `updatedAt` resolves after a save (baseline reset, like the old note editor) — content is preserved from the snapshot; caret position is not. Accepted and consistent with the previous editor.
- **Known shape, recorded for Phase 07:** the panel is the runner's future home — `CodePanel` view mode + `snippet.verdict` + authored tests from Phase 03 need no rework; `?lang=` deep-link plumbing for the problem page was *removed* during budget trims (nothing generates those links yet) and can return with the runner.
- **Budget fragility is real and flagged, not hidden.** 35 B of headroom means the next phase starts in deficit: it must find equal cuts or stop for the owner's cap gate (the approved one-time re-baseline belongs to Phase 09). Determinism note: local and CI both run Node 22 + the checked-in lockfile, so `dist` and its gzip sizes are byte-stable; this was verified by reproducing the budget script's exact sum locally.
- **Small leftovers, deliberately kept:** `src/FriendsView.tsx` still uses the pre-existing `.code-preview` class for invite codes (unrelated to snippets; `.code-view` layers on it for the peek `<pre>`). The detached baseline worktree used for bundle attribution lived outside the repo and nothing from it ships.
